GarrisonFarm GPU 加速补丁（DirectML 版）
==========================================

适用版本：GarrisonFarm 个人优化版 v1.1 / v1.2（及其 _internal 结构相同的版本）
测试环境：Windows + RTX 4060 Ti + AMD Ryzen 5 7500F（6 核 12 线程）+ MuMu 12


一、为什么要打这个补丁
----------------------
这个程序的 CPU 占用几乎全部来自「文字识别」（OCR）。
它内置的是 rapidocr + onnxruntime 的 CPU 版本，配置里线程数是 -1（不限制），
所以每次识别都会把所有 CPU 核心拉满，识别一张商店卡片就会占满 5~8 个核心，
准备阶段连续刷新商店时，CPU 就是长时间 100% —— 这就是你感觉「CPU 占用过高」的原因。

本补丁做两件事：
  1. 把 _internal\onnxruntime 换成 DirectML(GPU) 版本，让文字识别跑在显卡上；
  2. 把 _internal\rapidocr_onnxruntime\config.yaml 里的 use_dml 打开（检测/方向/识别三项）。

用的是 DirectML（Windows 自带的 DX12 推理后端），不需要安装 CUDA、cuDNN，
NVIDIA / AMD / Intel 显卡都能用，也不改程序本身的任何逻辑和代码。


二、本机实测效果（同一帧 1920x1080 游戏画面，各区域重复识别取平均）
------------------------------------------------------------------
区域（原图坐标）              原版 CPU 版                    本补丁 DirectML 版
商店 5 张卡 (180,770)-(1700,1060)
                              551 ms 耗时 / 2975 ms CPU 占用   162 ms / 185 ms
                              （≈5.4 个核心满载）              （≈1.1 个核心）
右上信息 (1440,150)-(1920,800)
                              132 ms / 965 ms（≈7.3 核）       98 ms / 123 ms
资金数字 (1785,768)-(1850,816)
                              99 ms / 773 ms（≈7.8 核）        73 ms / 74 ms
顶部回合资金 (600,0)-(1300,120)
                              369 ms / 2031 ms（≈5.5 核）      166 ms / 166 ms

一次「刷新商店」的完整开销（截图 + 读 5 张卡 + 读资金）：
    原版：约 0.66 秒耗时，约 3.8 秒 CPU（相当于 5~6 个核心跑满）
    补丁：约 0.28 秒耗时，约 0.35 秒 CPU（1 个核心上下）
识别耗时本身也快了 2~3 倍，准备阶段会顺带变快一点。

识别结果对比：在商店、信息面板、资金、顶部、干员栏 5 个区域，CPU 版和 DirectML 版
输出的文字完全一致（逐条比对，无差异），不存在准确率下降的问题。


三、怎么装
----------
1. 关掉正在运行的 GarrisonFarm 黑窗口（必须关，否则文件被占用写不进去）。
2. 双击「安装GPU加速.bat」。
   它会自动在 桌面 / 下载 / 文档 / D 盘 / E 盘里找 GarrisonFarm 目录：
     - 只找到一个：直接用它；
     - 找到多个：列出序号，输入你要打补丁的那个（选错了也只要运行还原脚本即可）；
     - 一个都没找到：把 GarrisonFarm 文件夹拖进窗口回车。
   也可以直接把 GarrisonFarm 文件夹拖到「安装GPU加速.bat」图标上。
3. 看到「补丁安装完成」就好了，正常用「开始刷角标.bat」启动即可。

补丁会在程序目录里多留两样东西，不要删（删了就没法一键还原）：
    _internal\onnxruntime_cpu_backup\            原版 CPU 推理库备份
    _internal\rapidocr_onnxruntime\config.yaml.cpu_backup   原配置备份
另外会多一个 DirectML.dll（约 18 MB），总体积增加约 58 MB。


四、怎么确认真的在跑 GPU
------------------------
启动「开始刷角标.bat」后，自检那几行里会出现（三项，分别是检测/方向/识别）：

    OrtInferSession - INFO: Windows 10 or above detected, try to use DirectML as primary provider

出现这一行就说明 GPU 生效了。
再打开任务管理器看 GarrisonFarm.exe：CPU 应该只有 1 个核心上下波动（原来准备阶段是全核 100%）。


五、想改回去
------------
双击「还原CPU版.bat」，选同一个程序目录，就恢复成原版 CPU 模式（DirectML.dll 会被删掉，
配置也会还原）。这个操作可以反复来回切换。


六、备用方案：不想用 GPU，只想把 CPU 压下来
--------------------------------------------
双击「备用-限制CPU线程.bat」，把线程数限制成 2 / 4 / 6：
    - 线程越少，CPU 占用峰值越低，识别越慢；
    - 4 线程大致能用 4 个核心跑满，识别速度约为原来的 60%~70%。
这个选项和 GPU 补丁不冲突（GPU 生效时基本用不到它，只有显卡不可用时才会回落到 CPU）。


七、注意
--------
1. 只支持 Windows 10 及以上（DirectML 的要求），显卡需要支持 DirectX 12。
2. 显卡驱动请保持较新版本（NVIDIA 472 以上均可，本机 576.28 实测正常）。
3. 以后如果升级了 GarrisonFarm（换了新的 _internal 文件夹），补丁会失效，
   重新运行一次「安装GPU加速.bat」即可。
4. 补丁只替换推理库和一份配置，不改 GarrisonFarm.exe，也不联网、不写注册表。
5. 若遇到识别异常，先运行「还原CPU版.bat」确认是否与补丁有关；还原后仍异常则是原程序问题。


八、如果还想更快（可选，未包含在本包里）
----------------------------------------
- 走 CUDA 而不是 DirectML：能再快一些，但要额外装 CUDA 12 + cuDNN 9 运行库（约 1 GB），
  在本机这种小尺寸 OCR 场景下收益有限（DirectML 已经只占 1 个核心），不建议折腾。
- 真正的下一个瓶颈已经不是识别，而是游戏的动画等待和点击间隔，那属于程序本身的节奏控制。
